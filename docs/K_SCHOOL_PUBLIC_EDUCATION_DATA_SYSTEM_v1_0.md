# K-School 공공교육 정책 데이터 시스템 설계 v1.0
## school.hondi.net — 개인 교습이 아니라, 공공 교육 현황·정책 데이터 생산 시스템으로

> 관계 문서: [`health/docs/K_HEALTH_PUBLIC_HEALTH_DATA_SYSTEM_v1_0.md`](../../health/docs/K_HEALTH_PUBLIC_HEALTH_DATA_SYSTEM_v1_0.md) · [`insurance/docs/PDV_SANDBOX_EXECUTION_DESIGN_v1_0.md`](../../insurance/docs/PDV_SANDBOX_EXECUTION_DESIGN_v1_0.md) · [`insurance/docs/PDV_SANDBOX_SCHEMA_v1_0.md`](../../insurance/docs/PDV_SANDBOX_SCHEMA_v1_0.md) — 이 문서는 K-Health와 동일한 원리(코드를 PDV로 보내 집계)를 교육 도메인에 적용한다.
> **범위 정정**: 기존 `docs/K-School_WhitePaper_v1.0.md`가 다뤄온 "학생 개인의 나이·성격·관심사·진로에 완전히 맞춤화된 AI 교수"는 K-School이 아니라 **전문가 AI 페르소나(가칭 K-Professor, `gopang/src/gopang/ai/expert-registry.js`에 정식 등록 여부 논의 중 — TODO 주석 참고)**의 역할이다. `desktop.html`을 비롯한 기존 개인 교습 콘텐츠는 이 문서의 범위가 아니며 별도로 처리된다. 이 문서가 다루는 **K-School**은 오직 **다수의 PDV를 집계해 공공 교육 현황을 파악하고 정책 데이터를 생산하는 시스템**이다.

## 0. K-Health와 구조가 같다 — 무엇이 대응되는가

| K-Health | K-School |
|---|---|
| 환자 PDV(자기보고 증상) | 학습자 PDV(자기 학습 기록·자기평가) |
| 의료진·기관 PDV(실제 진단·처치) | **교수 AI 페르소나의 PDV**(세션마다 남기는 실제 평가·채점 기록) |
| "진료 접근성 격차"(자기보고 vs 실제진단 괴리) | **"이해도 착시 격차"**(자기평가 vs 실제평가 괴리, §5) |
| ICD 대분류 단위 집계 | 교육과정 대단원/성취기준 단위 집계 |
| 소규모 셀 억제(재식별 방지) | 동일 원리, 그대로 적용(§3) |
| 낙인 질환 별도 임계값 | 특수교육 대상·학습부진 등 민감 범주 별도 임계값(§3.3) |

**교수 AI 페르소나의 PDV가 핵심 차이점이다.** K-Health는 "의료진"이라는 인간이 남긴 PDV를 두 번째 소스로 썼지만, K-School은 두 번째 소스가 **AI 페르소나 자신의 상호작용 기록**이다 — 페르소나가 매 세션마다 6하원칙으로 "무엇을 가르쳤고, 어떤 질문에 학생이 어떻게 답했고, 실제로 무엇을 채점했는지"를 스스로 PDV에 남긴다고 전제한다. 이건 사람이 아니라 AI가 생성하는 기록이므로, 아래 원칙들이 K-Health보다 한 겹 더 필요하다(§2.2).

## 1. K-School이 실제로 할 수 있는 일 — 스코프 정정

- **교육부·시도교육청의 공식 학업성취도 통계를 대체·사칭하지 않는다.** K-Health가 보건복지부를 사칭했던 실수를 반복하지 않는다 — 모든 화면에 "고팡 이용자 표본 기반 자체 집계, 공식 통계 아님"을 고정 고지한다(K-Health §6-1과 동일 원칙).
- **개별 학생 성적·평가를 다루지 않는다.** 이 시스템의 출력 단위는 항상 "교육과정 대단원 × 학년군 × 지역(광역 단위 이상) × 월/학기"처럼 충분히 넓은 집계이며, 특정 학생 1인의 성취도로 내려가는 조회 경로 자체를 만들지 않는다.
- **표본 편향을 항상 병기한다.** 고팡 이용자·교수 페르소나 이용 학생으로 표본이 제한된다.

### 2.1 학습자 PDV 소스

학생이 스스로 "이해했다"고 느낀 정도, 학습 시간, 자기 진도 체크 등 — 자기보고 성격의 기록.

### 2.2 교수 페르소나 PDV 소스 — K-Health와 다른 지점

의료진 PDV는 **사람이 실제로 관찰·판단해 남긴 기록**이라 신뢰도의 기준이 비교적 명확하지만, 교수 페르소나 PDV는 **AI 자신이 채점·평가한 기록**이므로 추가 원칙이 필요하다:

- **페르소나의 평가 자체가 편향·오류를 포함할 수 있다는 전제를 명시한다.** K-School이 "페르소나 채점 = 객관적 진실"로 취급하면, 페르소나의 채점 편향이 그대로 정책 데이터의 편향이 된다. 따라서 페르소나 PDV 기록에는 항상 **채점에 쓰인 모델·버전·채점 기준(rubric) 식별자**를 함께 남기고, 집계 시 모델·버전별로 층화(stratify)해 특정 버전의 편향이 전체 통계를 왜곡하지 않게 한다.
- **페르소나 자기 자신의 세션 로그이므로, 이해상충 여지가 있다.** 페르소나가 "내가 잘 가르쳤다"는 방향으로 스스로 유리하게 기록할 유인이 구조적으로 없어야 한다 — 페르소나 PDV 기록 스키마 자체(무엇을 몇 시에 가르쳤고 어떤 질문에 어떤 채점을 했는지)는 페르소나가 사후에 편집할 수 없는 append-only 구조로 설계하고, OpenHash 앵커링으로 사후 변경 자체를 차단한다(이 부분은 원본 PDV 기록 메커니즘의 일반 원칙이지만, "평가자가 곧 평가 대상"인 이 케이스에서 특히 중요하다).

## 3. 소규모 셀 억제 — K-Health와 동일 원리, 재사용

`health/k-health-privacy-utils.js`의 `suppressSmallCells()`·`suppressWithHistoryGuard()`는 **도메인에 의존하지 않는 순수 함수**로 이미 구현·테스트(11/11 통과)되어 있으므로, K-School은 이를 그대로 재사용한다(중복 구현하지 않는다 — §7 참고).

### 3.1 교육 도메인 특유의 민감 범주

`STIGMA_SENSITIVE_DISEASE_GROUPS`(K-Health)에 대응하는 교육 버전이 필요하다:

```js
// K-School 버전 — school/docs 검토 전까지 잠정치, 정책 검토위원회 확정 필요
const SENSITIVE_LEARNER_CATEGORIES = [
  // 예시 — 실제 목록은 교육 전문가·특수교육 당사자 자문을 거쳐 확정 전까지 비워둔다.
  // { code: 'SPED', name: '특수교육 대상', k: 20 },
  // { code: 'LOW_ACHIEVE', name: '학습부진(하위 누적)', k: 20 },
  // { code: 'MULTICULTURAL', name: '다문화가정 학생', k: 20 },
];
```

- 특수교육 대상·학습부진·다문화가정처럼 소수이면서 낙인 위험이 있는 범주는 일반 학년군 통계보다 높은 k값을 적용한다.
- "OO중학교 특수교육 대상 학생 3명 중 2명이 이번 달 결석"처럼, 학교 단위로 내려가면 절대 다수 케이스에서 재식별 위험이 생긴다 — 학교 단위 집계는 원칙적으로 하지 않고 시군구 단위 이상으로 시작한다(K-Health가 시도 단위 이상으로 시작한 것보다 더 보수적으로 잡는다 — 학교라는 단위 자체가 병원보다 훨씬 작고 폐쇄적인 커뮤니티이기 때문).

## 5. 교차 검증 — "이해도 착시 격차"

```
자기평가 이해도(학습자 PDV) vs 실제 평가 점수(교수 페르소나 PDV)
   → 격차가 크게 벌어지는 단원·학년군을 "이해도 착시 의심 구간"으로 플래그

플래그 조건 (초안 — 실측 데이터로 보정 필요, K-Health §5와 동일 구조):
   자기평가 "이해함" 비율 - 실제평가 "충족" 비율 > 임계값(예: 20%p) 이고
   해당 구간 표본 수가 소규모 셀 억제 기준(k) 이상일 때
```

**정책적 가치**: "학생이 이해했다고 느끼지만 실제로는 못 따라가는" 단원을 조기에 잡아낼 수 있다 — 이건 시험 성적(사후 확인)이나 설문(자기보고만)만으로는 못 보는, 두 소스를 겹쳐야만 보이는 지표다. K-Health의 "진료 접근성 격차"가 "증상은 있는데 병원을 못 간 사람"을 잡아내는 것과 정확히 같은 논리 구조다.

이 결과도 §3의 소규모 셀 억제를 통과해야 정책 결정자에게 노출된다.

## 6. `dashboard.html` 재구축 원칙

K-Health §6과 동일한 4원칙을 그대로 적용한다:
1. 표본 편향 고지 상단 고정
2. 개별 학생 단위 정밀 지표는 다루지 않음(학교 단위도 원칙적으로 배제 — §3.1)
3. "이해도 착시 격차"(§5)를 핵심 대시보드로 삼는다
4. 실시간·LIVE 프레이밍 없음 — 학기/월 단위 집계, 명시적 기준 시점 표시

## 7. 코드 재사용 원칙

`k-health-privacy-utils.js`는 이미 도메인 비의존적으로 설계돼 있으므로(셀 키 문자열과 카운트만 다루고, "질병"이나 "환자"라는 개념에 의존하는 로직이 없다), K-School은 **새 파일을 만들지 않고 이 모듈을 그대로 import해 재사용**한다. 필요한 것은:

- `SENSITIVE_LEARNER_CATEGORIES`(§3.1)처럼 도메인별 민감 범주 목록만 K-School 쪽에서 별도로 선언
- `flagAccessGap()`은 함수명이 의료 도메인 명칭이지만 실제 로직(비율 A vs 비율 B의 격차 판정)은 도메인 무관 — K-School에서는 `flagComprehensionIllusion()`이라는 얇은 래퍼로 재노출하는 것을 권장(가독성 목적, 로직 중복 아님)

## 8. 단계적 로드맵

| 단계 | 범위 |
|---|---|
| 0단계 | 캡슐 키 화이트리스트(§4) 확정, 민감 범주 목록(§3.1) 교육 전문가 검토, `k-health-privacy-utils.js` 재사용 래퍼 작성 |
| 1단계 | 학습자 PDV 단일 소스로 시작(자기평가 집계만), 표본 편향 고지 포함한 `dashboard.html` 재구축 |

| 3단계(장기) | 표본이 통계적으로 유의미해지면 교육부·시도교육청과의 협의 검토(법률·행정 자문 선행 필수) |
